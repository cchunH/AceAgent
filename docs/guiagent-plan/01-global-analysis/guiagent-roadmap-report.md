# GUIAgent 落地路线图报告（分阶段实施）

## 1. 路线总览

总体策略：**契约先行 -> 单机闭环 -> 规模化分发**。  
目标是在不破坏现有可运行系统的前提下，逐步构建 GUIAgent 核心能力。

## 2. 分阶段计划

### Phase 0：基线与契约（1~2 周）

目标：
- 建立统一数据契约与评估指标。

交付：
- `IntentKey`/`IntentMetadata`/`AnchorNode`/`BlueprintPatch` schema。
- 指标埋点：成功率、步耗时、S2 接管率、重试率、失败类型。

验收：
- 新旧链路都能写出统一结构化日志。

### Phase 1：状态面 MVP（2~4 周）

目标：
- 实现最小可用的主辅锚点识别与页面拓扑确认。

交付：
- 锚点评分与筛选器（Top/Bottom 区域优先）。
- 法定人数匹配（Quorum）与页面置信度输出。

验收：
- 在目标 App 的关键页面，状态识别稳定性达到可用阈值。

### Phase 2：动作面 MVP（2~4 周）

目标：
- 实现仿射投射 + 执行前语义断言 + 执行后状态确认。

交付：
- `AffineRuntime`（相对坐标 -> 绝对坐标）。
- `PreAction Sense Check` 与 `PostCondition Match`。
- L1/L2/L3 分级自愈策略。

验收：
- 相比旧链路，误触率和失败中断率显著下降。

### Phase 3：蓝图编译执行（3~5 周）

目标：
- 将“任务经验”升级为可运行蓝图。

交付：
- 本地 `Blueprint Hub`（版本化蓝图存储）。
- 编译执行器（大脑授权 -> 小脑断言执行）。
- 与现有 Planner 的适配层。

验收：
- 高频场景执行延迟下降，S2 参与频次明显降低。

### Phase 4：离线进化与差分补丁（3~5 周）

目标：
- 将失败恢复与成功轨迹转化为热修复补丁。

交付：
- 多帧交集“幽灵骨架”提取。
- 差分补丁生成与回滚机制。

验收：
- UI 小改版可通过补丁自动恢复，不依赖人工重标。

### Phase 5：群智网络（后置，4~8 周）

目标：
- 建立 Swarm Hub：上报、共识、灰度、下发。

交付：
- 脱敏管线、Canary 验证、补丁信任分级。
- 热更新分发机制。

验收：
- 一个节点修复可在群体中稳定复现且无安全回归。

## 3. 风险清单与缓解策略

1. 风险：状态面鲁棒性不足  
- 缓解：先限定场景（Top/Bottom 稳定区），逐步扩展中区复杂场景。

2. 风险：协议改造影响主链稳定  
- 缓解：采用并行子系统和开关路由，不在主链直接替换。

3. 风险：补丁误更新造成群体回归  
- 缓解：必须先灰度再全量，强制回滚阈值。

4. 风险：隐私合规压力  
- 缓解：群智阶段默认本地脱敏与最小化上报字段。

## 4. 资源建议

- 角色配置（最小）：  
- 架构/后端 1 人（协议与编排）  
- 感知/算法 1 人（状态面与匹配）  
- 客户端/执行 1 人（动作面与设备层）  
- QA/自动化 1 人（回归与指标验证）

## 5. 最终建议

先把 Phase 0~3 做成“单机确定性闭环”，再启动群智网络。  
这是实现 GUIAgent 蓝图且控制风险的最短路径。
