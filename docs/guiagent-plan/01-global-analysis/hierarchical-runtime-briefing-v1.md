# GUIAgentV2 五分钟汇报版（机制实现现状）v1

## 1. 目标一句话

把 GUI 自动化从“每步都临时推理”升级为“可规划、可校验、可复用、可审计”的分层执行系统。

## 2. 当前已经实现了什么

1. 分层计划：复杂指令先拆为 `steps + subtasks`，而不是直接单步试探。
2. 页面门禁：每步执行前做 `page_hint + 拓扑 + 指纹ID` 一致性检查，错页直接阻断。
3. 原子执行闭环：动作后强制走 `assertion + post_check`，不是“点了就算成功”。
4. 退化保护：复杂任务若被退化成 `Wait`，触发 `intent_parse_guard`，防止假成功。
5. 经验回灌：`blueprint_sync` 回写页面绑定元数据，支持后续复用与回放质量控制。
6. 双重验收：`flow_audit` 检流程合法，`validation_gate` 检结果质量。

## 3. 现在这套机制的执行形态

`用户指令 -> 分层计划 -> 子任务页面门禁 -> 原子动作执行 -> 断言/后检 -> 任务结束 -> 蓝图回灌 -> 审计验收`

直观理解：
- 模型主要负责“计划和纠偏决策”；
- 执行器主要负责“可控动作落地”；
- 状态面主要负责“确认是否走在对的页面和对的轨道上”。

## 4. 为什么复杂任务还没完全稳定

核心不是链路缺失，而是“环境与依赖稳定性”仍在收敛：
1. 视觉/感知依赖（如 modelscope 相关链路）版本兼容容易导致中途失败。
2. 复杂任务需要更稳定的页面指纹主键体系和阈值标定，而不只是运行时临时值。
3. 需要更多实机样本做门禁阈值收敛（不同机型、不同 UI 扰动）。

## 5. 当前完成度（工程视角）

- 主链路能力：`约 75%~80%`
- 复杂任务稳定实测能力：`约 55%~65%`
- 进入“可持续迭代实测”阶段：`已具备条件`

## 6. 接下来最关键的三步

1. 固化运行环境
- 锁定一套可复现环境（Python/核心包版本），避免每次被依赖漂移打断。

2. 打通复杂任务主回归
- 用固定任务集执行 device 回归，重点观察：
  - `page_hint_gate`
  - `intent_parse_guard`
  - `assertion/post_check`
  - `blueprint_sync`

3. 做阈值与主键收敛
- 把页面指纹从“运行时生成”推进到“仓内稳定主键管理”；
- 用回归数据标定门禁阈值，减少误阻断与漏放行。

## 7. 对外汇报口径（可直接说）

“我们已经完成了分层规划、页面门禁、闭环校验、回灌沉淀和双重审计五个核心环节，系统不再是单步试探。当前主要瓶颈不是架构缺失，而是复杂任务在实机与依赖环境下的稳定性收敛。下一阶段将通过固定环境 + 固定任务集 + 阈值标定，把机制从可运行推进到稳定可复现。”
