## 文档元信息

- 状态：`active`
- 版本：`v1.0`

- 审查依据：`GUIAgent/01~11` 原蓝图文档 + 当前 `guiagent_v2` 代码主线

## 1. 总体结论（先给结论）

1. 方向未走偏。
- 当前改造仍沿着蓝图主轴推进：`大脑授权 -> 蓝图导航 -> 小脑验证执行 -> 认知回灌`。
- 现有实现已具备快路径执行骨架、边界自愈基础、离线复盘入口与在线快速匹配能力。

2. 但尚未完成“蓝图全闭环”。
- 已完成：执行与治理骨架、状态面基础算法、控制面可查询接口。
- 未完成：群智联邦分发、生产级长期数据面、向量检索网关、复杂场景鲁棒算法。

3. 当前建议继续遵循“功能优先、稳定性后置”的执行策略。
- 在保证可运行前提下，先补齐关键功能闭环（R10/R11），再做生产化硬化（R12/R13+）。

## 2. 原蓝图关键流程（复刻版）

本节严格按蓝图叙事抽象流程，不按代码文件切块。

### 2.1 流程 A：编译导航快路径（主流程）

1. 大脑授权意图（Intent Authorization）
- 输出标准化意图 Key，而非自由文本动作。

2. 蓝图给出导航建议
- 提供目标页面静态骨架、锚点拓扑、动作相对坐标、后置预期。

3. 小脑一级雷达：全局拓扑校验
- 使用主辅锚点判定“是否在正确页面 / 坐标系是否成立”。

4. 小脑二级雷达：局部语义断言（Sense Check）
- 在目标执行区域核验语义是否与意图 Key 对齐。

5. 几何投射执行
- 基于仿射变换将相对坐标映射到当前设备绝对坐标并执行。

6. 后置状态确认
- 对比动作后指纹与蓝图预期状态，判定是否生效。

7. 微扰与降级
- 执行无效则微扰重试（L1），环境偏离则逻辑降级（L2）。

8. 失败接管
- 持续失败触发大脑接管（L3）。

### 2.2 流程 B：导航偏离与自愈协议（边界工程）

1. 识别偏离类型
- 模态弹窗（Z 轴遮挡）
- 加载抖动/网络异常
- 语义冲突（目标语义与意图不一致）

2. 分级响应
- L1 微扰重试
- L2 逻辑重置（刷新/回退）
- L3 大脑重规划

3. 反馈沉淀
- 将偏离上下文与修复路径进入离线复盘。

### 2.3 流程 C：离线进化与认知回灌

1. 经验采集
- 路径 A：System 1 成功快路径轨迹
- 路径 B：System 2 成功接管轨迹（黄金样本）

2. 幽灵骨架提取
- 多帧交集去噪，提取静态骨架与动态槽位。

3. 差分修复
- 对蓝图进行最小 Delta 更新，而非全量重写。

4. 版本化发布
- 新蓝图切片入库并提升后续在线命中率。

### 2.4 流程 D：群智联邦传播（蓝图 06/11）

1. 脱敏上报
2. 灰度共识
3. 全网热更新

备注：该流程目前尚未进入代码主线。

## 4. 方向偏移检查（是否走偏）

1. 未偏移项
- 保持了“意图驱动 + 拓扑校验 + 几何执行 + 后验闭环”的主链。
- 保持了“移动端主链优先，web_skill 旁路增强”的边界。

2. 需要警惕的偏移风险
- 如果后续只强化模块能力而不按流程串联，会回到“功能堆叠但闭环断裂”。
- 如果过早做生产化分布式改造，可能挤压核心算法完成度。

## 5. 向量库接入评估（明确回答）

### 5.1 当前状态

- 当前主线没有真正接入向量库（FAISS/Qdrant/Milvus/pgvector 均未接入）。
- 当前快速匹配基于骨架签名与集合相似度，属于结构匹配，不是向量检索。

### 5.2 是否需要引入

结论：需要，但不应抢在功能闭环之前。

建议定位：
1. 意图对齐网关（蓝图 04）
- 将“模型自由输出”映射到标准意图 Key，可使用向量召回做候选。

2. 蓝图召回层（蓝图 02/05）
- 对 skeleton/anchors/text aliases 构建多路 embedding，做 top-k 候选召回。

3. 异常聚类与回灌优先级排序（蓝图 11）
- 将失败样本向量化聚类，优先修复高频故障簇。

### 5.3 接入时序（功能优先）

1. 阶段 F1（现在-下一迭代）
- 维持当前结构匹配主线，不阻塞功能闭环。

2. 阶段 F2
- 引入 `VectorIndexAdapter` 抽象，先接本地轻量后端（可选 FAISS）做离线召回实验。

3. 阶段 F3
- 接入在线向量服务（Qdrant/Milvus/pgvector），再与控制面指标联动。

## 6. 架构缺口（在可运行前提下的优先补齐）

1. 缺口 A：流程级编排协议仍偏“文件级耦合”
- 需要把“流程状态机”从 `v2_executor` 进一步抽离。

2. 缺口 B：离线复盘产物的质量门槛不足
- 需增加复盘样本评分与自动回滚条件。

3. 缺口 C：向量召回缺位
- 需补意图对齐与蓝图召回的召回层抽象。

4. 缺口 D：群智联邦未实现
- 当前仅本地进化，无共享共识与灰度传播。

## 7. 下一阶段主计划（功能优先）

### 7.1 目标排序

1. 先功能闭环
- 完成“在线执行-离线回灌-在线再命中”的稳定循环。

2. 再稳定性强化
- 做长期数据治理、跨节点一致性、生产化门禁。

### 7.2 执行阶段

1. R10（功能）
- 强化执行链：复杂网页/动态页面重规划与证据链。

2. R11（功能）
- 强化状态面：离线复盘评分、回灌策略、快速匹配命中提升。

3. R12（稳定）
- 回归矩阵、发布门禁、失败样本归档。

4. R13（算法+检索）
- 引入向量召回适配层并做离线 A/B。

## 8. 验收标准（防止“模块拼接”）

1. 流程一致性
- 每次改造必须声明影响 `流程 A/B/C/D` 的哪一步。

2. 证据一致性
- 必须有对应事件字段和指标可观测（而非仅代码存在）。

3. 闭环一致性
- 同一类场景必须验证“在线失败 -> 复盘更新 -> 下次在线命中”。

4. 向量检索门槛
- 在进入在线服务前，离线召回必须达到预设 recall 指标。

## 9. 最终判断

当前整体方向与 GUIAgent 原蓝图一致，且“功能优先”的策略是正确的。
下一阶段重点不是扩模块，而是把蓝图流程的关键链路做成可度量、可回灌、可复用的工程闭环。
