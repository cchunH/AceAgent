# GUIAgent 文档规范（v1）

目标：统一 `docs/guiagent-plan/` 的文档结构、命名与评审标准，降低沟通与执行偏差。

## 1. 文档结构规范

每份执行类文档建议包含以下块：
1. 标题
2. 目标一句话
3. 文档元信息（状态、版本、更新时间、适用阶段）
4. 主体内容（按编号章节）
5. 如适用：验收标准 / 风险 / 版本规则

状态枚举：
- `draft`：草案，尚未冻结
- `active`：可执行版本
- `template`：模板文档
- `deprecated`：废弃版本

## 2. 命名规范

- 文件名：`kebab-case` + 阶段标识（如 `*-v0.md`）。
- 版本后缀：
- `v0`：可用草案（允许增量改动）
- `v1+`：冻结版本（破坏性改动需迁移说明）

## 3. 术语规范

固定术语：
- `legacy`：现有 Uni-Mind 链路
- `guiagent_v2`：新链路
- `System 2`：大脑（规划/接管）
- `System 1`：小脑（执行/断言）
- `IntentKey`：`domain:verb:object`

禁止混用：
- 不使用“新系统/旧系统”替代 `legacy/guiagent_v2`。
- 不使用未定义缩写。

## 4. 链接与索引规范

- 新增文档必须同时更新：
- `docs/guiagent-plan/README.md`

- 相互引用优先使用相对路径，避免路径漂移。

## 5. 评审与冻结规范

- 每周一次文档评审，结论必须包含：
- 是否冻结版本
- 是否可进入下一阶段
- 阻塞项列表（如有）

- 文档冻结条件：
- 术语一致
- 指标口径无歧义
- 验收标准可执行
