# 论文图表结构化代码包 v1

## 1. 文档用途

本文档提供更适合 `draw.io / Mermaid` 使用的结构化代码，重点覆盖以下 4 张图：

1. `图4-3 智能体任务执行全生命周期时序图`
2. `图4-4 系统逻辑数据模型与实体关系图`
3. `图5-3 闭环校验与异常自愈流程图`
4. `图5-4 认知回灌与蓝图热修复流程图`

使用建议：

1. `draw.io`
- 打开 `插入 -> 高级 -> Mermaid`
- 直接粘贴下面代码
- 如果某类图在 draw.io 中渲染不稳定，优先使用文中给出的 `兼容版 flowchart`

2. `Mermaid Live Editor`
- 先在 Mermaid 中预览
- 再导入到 draw.io 或截图后手工复刻

3. `论文终稿`
- Mermaid 适合出草图与结构图
- 最终版本建议在 draw.io 中统一字体、对齐和颜色后导出

## 2. 图4-3 智能体任务执行全生命周期时序图

说明：

- 原始的 `图4-3` 如果把成功路径、蓝图命中/未命中分支、前后置校验、异常回退、回灌更新全部放进一张图，会比较拥挤。
- 更适合论文正文的做法是拆成两张配套图：
  1. `图4-3(a) 主成功链路时序图`
  2. `图4-3(b) 异常回退与重规划时序图`
- 正文中仍可统一称为“图4-3”，子图分别标注 `(a)` 与 `(b)`。

### 2.1 推荐用途

- 第 4.3 节正文插图
- 重点体现：输入、检索、执行、校验、回灌、反馈

### 2.2 图4-3(a) 主成功链路时序图

这张图只保留“正常执行成功”的主链路，用于说明系统的标准任务处理流程。

```mermaid
sequenceDiagram
    autonumber
    participant U as 用户
    participant P as 战略推理层
    participant K as 知识沉淀层
    participant E as 反应执行层
    participant D as 移动设备

    U->>P: 输入自然语言任务
    P->>P: 解析意图并拆解任务
    P->>K: 查询蓝图候选
    K-->>P: 返回候选蓝图与拓扑指纹
    P->>E: 下发意图契约

    E->>D: 获取当前界面状态
    D-->>E: 返回感知结果
    E->>E: 拓扑匹配
    E->>E: 前置断言
    E->>D: 执行点击/滑动/输入
    D-->>E: 返回执行后状态
    E->>E: 后置校验

    E->>K: 回灌成功轨迹
    K->>K: 更新蓝图与索引
    E-->>U: 返回执行结果
```

### 2.3 图4-3(b) 异常回退与重规划时序图

这张图专门用于说明：

1. 前置断言失败
2. 后置校验失败
3. 反馈回推理层重规划

```mermaid
sequenceDiagram
    autonumber
    participant U as 用户
    participant P as 战略推理层
    participant K as 知识沉淀层
    participant E as 反应执行层
    participant D as 移动设备

    U->>P: 输入自然语言任务
    P->>P: 解析意图并拆解任务
    P->>E: 下发意图契约

    E->>D: 获取当前界面状态
    D-->>E: 返回感知结果
    E->>E: 拓扑匹配与前置断言

    alt 前置断言失败
        E-->>P: 反馈环境冲突
        P->>P: 触发局部或全局重规划
        P->>E: 下发修正意图契约
    else 前置断言通过
        E->>D: 执行物理动作
        D-->>E: 返回执行后状态
        E->>E: 后置校验
        alt 后置校验失败
            E->>E: 微扰重试
            E-->>P: 反馈执行偏离
            P->>P: 触发局部重规划
            P->>K: 查询补丁与相似蓝图
            K-->>P: 返回候选修复结果
            P->>E: 下发修正意图契约
        else 后置校验通过
            E-->>U: 返回执行结果
        end
    end
```

## 3. 图4-4 系统逻辑数据模型与实体关系图

### 3.1 推荐用途

- 第 4.4 节正文插图
- 目标是让传统软件工程评审快速理解“实体、字段、关系”

### 3.2 Mermaid 类图版

说明：
- `classDiagram` 比 `erDiagram` 更适合表达字段
- 这版更适合作为论文逻辑数据模型图

```mermaid
classDiagram
    class 用户意图 {
        +意图主键
        +原始指令
        +标准意图键
        +提交时间
    }

    class 任务蓝图 {
        +蓝图主键
        +意图键
        +版本号
        +目标状态
        +应用域
    }

    class 拓扑指纹 {
        +指纹主键
        +骨架签名
        +稳定度
        +锚点数量
    }

    class 原子动作 {
        +动作主键
        +动作类型
        +动作参数
        +顺序号
    }

    class 运行任务 {
        +运行主键
        +任务状态
        +提交时间
        +完成时间
    }

    class 运行事件 {
        +事件主键
        +事件类型
        +时间戳
        +状态码
    }

    class 蓝图补丁 {
        +补丁主键
        +目标蓝图
        +补丁版本
        +修复说明
    }

    用户意图 "1" --> "多" 任务蓝图 : 对应
    任务蓝图 "1" --> "多" 原子动作 : 包含
    任务蓝图 "1" --> "1..多" 拓扑指纹 : 依赖
    任务蓝图 "1" --> "多" 蓝图补丁 : 更新
    运行任务 "1" --> "多" 运行事件 : 产生
    运行任务 "多" --> "1" 用户意图 : 来源于
    运行事件 "多" --> "1" 任务蓝图 : 引用
```

### 3.3 Mermaid E-R 简化版

说明：
- 如果 draw.io 对 `classDiagram` 字段渲染不好，可以退回这版
- 这版更简洁，但字段表现力弱

```mermaid
erDiagram
    用户意图 ||--o{ 任务蓝图 : 对应
    任务蓝图 ||--o{ 原子动作 : 包含
    任务蓝图 ||--|{ 拓扑指纹 : 依赖
    任务蓝图 ||--o{ 蓝图补丁 : 更新
    运行任务 ||--o{ 运行事件 : 产生
    运行任务 }o--|| 用户意图 : 来源于
    运行事件 }o--|| 任务蓝图 : 引用
```

### 3.4 draw.io 兼容版 flowchart

说明：
- 如果你想要最稳的导入效果，建议用这一版
- 每个实体用一个字段盒子表示，适合后期手工微调

```mermaid
flowchart TB
    UI["用户意图<br/>- 意图主键<br/>- 原始指令<br/>- 标准意图键<br/>- 提交时间"]
    BP["任务蓝图<br/>- 蓝图主键<br/>- 意图键<br/>- 版本号<br/>- 目标状态<br/>- 应用域"]
    TF["拓扑指纹<br/>- 指纹主键<br/>- 骨架签名<br/>- 稳定度<br/>- 锚点数量"]
    AC["原子动作<br/>- 动作主键<br/>- 动作类型<br/>- 动作参数<br/>- 顺序号"]
    RT["运行任务<br/>- 运行主键<br/>- 任务状态<br/>- 提交时间<br/>- 完成时间"]
    EV["运行事件<br/>- 事件主键<br/>- 事件类型<br/>- 时间戳<br/>- 状态码"]
    PT["蓝图补丁<br/>- 补丁主键<br/>- 目标蓝图<br/>- 补丁版本<br/>- 修复说明"]

    UI -->|对应| BP
    BP -->|包含| AC
    BP -->|依赖| TF
    BP -->|更新| PT
    RT -->|来源于| UI
    RT -->|产生| EV
    EV -->|引用| BP
```

## 4. 图5-3 闭环校验与异常自愈流程图

### 4.1 推荐用途

- 第 5.3.2 节正文插图
- 用来说明执行闭环的核心控制机制

### 4.2 Mermaid 标准版

```mermaid
flowchart TD
    A[接收动作请求]
    B[执行前局部感知]
    C{目标区域是否匹配意图}
    D[前置语义断言]
    E[执行物理动作]
    F[采集执行后状态]
    G{界面状态是否符合预期}
    H[任务成功]

    I[阻断执行]
    J[微扰重试]
    K[局部重规划]
    L[蓝图热修复]

    A --> B --> C
    C -- 是 --> D --> E --> F --> G
    G -- 是 --> H

    C -- 否 --> I --> K --> A
    G -- 否 --> J --> K --> L --> A
```

### 4.3 draw.io 强化版

说明：
- 这一版把“正常路径”和“异常路径”分左右展开，导入后更容易排版

```mermaid
flowchart TB
    subgraph 主执行链路
        A[接收动作请求] --> B[执行前局部感知]
        B --> C{目标区域是否匹配意图}
        C -->|是| D[前置语义断言]
        D --> E[执行物理动作]
        E --> F[采集执行后状态]
        F --> G{界面状态是否符合预期}
        G -->|是| H[任务成功]
    end

    subgraph 异常恢复链路
        I[阻断执行]
        J[微扰重试]
        K[局部重规划]
        L[蓝图热修复]
    end

    C -->|否| I
    I --> K
    G -->|否| J
    J --> K --> L
    L --> A
```

## 5. 图5-4 认知回灌与蓝图热修复流程图

### 5.1 推荐用途

- 第 5.4.1 节正文插图
- 用来说明“成功轨迹 -> 差分 -> 补丁 -> 更新 -> 下次命中”的闭环

### 5.2 Mermaid 环形逻辑版

```mermaid
flowchart LR
    A[成功执行轨迹]
    B[差分分析]
    C[稳定锚点与骨架提炼]
    D[蓝图补丁生成]
    E[最小化热修复]
    F[蓝图库更新]
    G[下次任务快速命中]

    A --> B --> C --> D --> E --> F --> G --> A
```

### 5.3 Mermaid 分层版

说明：
- 这版更适合 draw.io
- 环状结构在部分工具里对齐不稳定，分层版更容易后期微调

```mermaid
flowchart TB
    A[成功执行轨迹]
    B[差分分析]
    C[稳定锚点提取]
    D[骨架与后置期望提炼]
    E[蓝图补丁生成]
    F[最小化热修复]
    G[蓝图库更新]
    H[下次任务快速命中]

    A --> B --> C --> D --> E --> F --> G --> H
    H -. 复用反馈 .-> A
```

### 5.4 draw.io 强化版

说明：
- 适合手工加图标
- 可以给 `A` 加勾选文档图标，给 `G` 加数据库图标，给 `E/F` 加补丁图标

```mermaid
flowchart LR
    subgraph 运行样本层
        A[成功执行轨迹]
    end

    subgraph 分析提炼层
        B[差分分析]
        C[稳定锚点提取]
        D[骨架与后置期望提炼]
    end

    subgraph 修复更新层
        E[蓝图补丁生成]
        F[最小化热修复]
        G[蓝图库更新]
    end

    subgraph 复用命中层
        H[下次任务快速命中]
    end

    A --> B --> C --> D --> E --> F --> G --> H
    H -. 经验复用 .-> A
```

## 6. 使用顺序建议

如果你现在准备真正绘图，建议按这个顺序来：

1. `图4-3`
- 最清晰，最容易先落地

2. `图5-3`
- 流程闭环很关键，答辩时也容易讲

3. `图5-4`
- 可和第 5 章创新点对应

4. `图4-4`
- 最后画，因为逻辑数据模型最容易反复改
