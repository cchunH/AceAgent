**设计视角**：定义系统指令的标准化协议。意图库是连接大脑（逻辑规划）、蓝图（经验存储）与小脑（物理执行）的唯一合法语言。通过“脑-控-行”契约，确保意图在流转过程中不发生语义偏移，并为小脑提供执行前的语义校验准则。

---

## 1. 核心定义与设计思辨 (Core Definition & Speculation)

### 1.1 大模型的“巴别塔”困境
大语言模型（LLM）天生具备发散性。若不加约束，同一动作在不同时刻会输出迥异的描述（如 "click like" vs "tap heart"）。这种语义漂移会导致经验复用失效。

### 1.2 “脑-控-行”契约：从发散到收敛
AceAgent-Swarm 引入 **系统意图库 (System Intent Library)** 作为最高契约：
*   **大脑 (System 2)**：意图的产生者。必须遵守契约，仅输出库内定义的标准 Key。
*   **蓝图 (Blueprint)**：意图的存储者。以标准 Key 索引拓扑指纹和动作矩阵。
*   **小脑 (System 1)**：意图的校验者。它不理解“发消息”的逻辑，但它依据契约库提供的“语义别名”，在执行前核对目标位置是否符合该意图。

---

## 2. 意图库数据结构设计 (The Schema)

我们采用分层、可扩展的 **DDD (Domain-Driven Design) 三段式结构**。

### 2.1 核心 Key 格式
`[Domain(App_ID)] : [Verb(动作原语)] : [Object(操作对象)]`
*   **Domain**: 应用包名或全局标识（如 `com.tencent.mm` 或 `GLOBAL`）。
*   **Verb**: 标准化动作原语（如 `TAP`, `SWIPE`, `INPUT`, `LONG_PRESS`）。
*   **Object**: 具体的业务功能对象（如 `SEND_BTN`, `SEARCH_BAR`）。

### 2.2 意图元数据 (Metadata) —— *增补：语义别名库*
每个 Intent Key 对应一个包含“执行准则”的 JSON 对象：
```json
{
  "key": "com.tencent.mm:TAP:SEND_BTN",
  "description": "点击聊天界面底部的发送按钮",
  "aliases": ["发送", "Send", "icon_hash:82a1f", "btn_green"], 
  "risk_level": "LOW",
  "pre_conditions": ["INPUT_BOX_NOT_EMPTY"],
  "post_expectations": ["MSG_LIST_REFRESH", "INPUT_BOX_CLEAR"]
}
```
*   **语义别名 (Aliases)**：这是为小脑设计的“避障雷达”凭据。包含文本、多语言描述及图标特征。

---

## 3. 强约束机制：确保契约履行 (Enforcement)

### 3.1 第一道防线：Prompt 层的枚举限制
利用 **Structured Output (JSON Mode)** 能力，在给大脑下发任务时，动态注入当前页面可行的动作枚举。大脑只能做“选择题”，禁止捏造新的 Key。

### 3.2 第二道防线：意图对齐网关 (Alignment Gateway)
针对模型输出的模糊意图进行“语义纠偏”：
*   **向量检索**：将模型原始输出与意图库中的 `description` 和 `aliases` 进行向量相似度比对。
*   **强制归一化**：相似度 > 0.92 的输出将被自动纠正为标准 Key。

### 3.3 第三道防线：意图驱动的小脑感知 (Intent-Driven Perception) —— *新增*
这是防止“失控”的核心逻辑。
*   **语义断言 (Sense Check)**：小脑在执行前，从小脑库中提取该 Key 对应的 `aliases`。
*   **匹配校验**：若大脑要点 `SEND_BTN`，但小脑在目标点附近扫描不到任何与“发送/Send/绿色按钮”相关的特征，小脑将**拒绝执行**并标记为“契约违约”。

---

## 4. 意图库的进化与扩容 (Evolution)

意图库通过 System 2 的“开荒”行为自动扩充：

1.  **新意图发现 (OOV Discovery)**：当大脑处理全新 App 或功能时，若无现成 Key，大脑可申请临时 `TEMPORARY_INTENT` 并通过 VLM 成功执行。
2.  **离线复盘与注册**：进化层（文档 05）在复盘成功轨迹时，会自动根据操作位置的语义特征生成新 Key（如 `com.app:TAP:NEW_FEAT`），并提取其视觉特征加入 `aliases`。
3.  **群体共识**：经 Swarm Hub（文档 06）多节点验证后，新 Key 正式转正，下发全网。

---

## 5. 总结 (Summary)

AceAgent-Swarm 的系统意图库实现了：
*   **指令确定性**：消除 LLM 的输出幻觉。
*   **感知确定性**：为小脑提供“执行前校验”的语义标尺。
*   **共享确定性**：确保不同 Agent 之间交流的是同一种“语言”，从而实现 Skill Blueprint 的无缝共享。
