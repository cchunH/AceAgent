## 一、 认知回灌 (Cognitive Back-propagation)：从“解决”到“记住”

在导航比喻中，如果司机发现原本的路修路了（UI 变更），并成功绕路到达终点，他必须把这条新路记录在地图上。

### 1. 经验捕捉 (Success Trace Capture)
当大脑（System 2）通过全量 VLM 推理成功完成了一次“避障”操作（如关闭了一个新出现的弹窗，或找到了改版后的按钮），进化层会立即捕获这一段 **“成功轨迹”**：
*   **输入**：异常时刻的旧指纹 + 大脑采取的修正动作 + 到达的目标新指纹。
*   **产物**：一段临时的“补丁序列”。

### 2. 骨架重构与意图再对齐
系统不会盲目合并所有动作。进化层会分析：这次改动是**临时遮挡**还是**永久改版**？
*   **临时遮挡**（如中秋节大促弹窗）：蓝图会增加一个“前置条件检查”，记录关闭该弹窗的步骤。
*   **永久改版**（如按钮从左边移到了右边）：系统会启动“幽灵骨架提取（文档 05）”，重新计算核心锚点星群，生成 **v2.0 版本的蓝图切片**。

## 二、 差分修正机制：极小化更新

为了保证效率，AceAgent-Swarm 遵循**“差分更新（Delta Update）”**原则，而不是每次都推翻重来。

*   **拓扑微调**：如果只是某个辅助锚点变了，系统只更新该锚点的特征向量，保持其他主锚点和几何坐标系不变。
*   **执行阈值漂移**：如果是因为光照或主题色导致视觉识别分下降，系统会自动微调该页面的“置信度阈值”，实现对环境变化的动态耐受。

## 三、 全网免疫：群智联邦的同步逻辑

AceAgent-Swarm 的真正威力在于：**一台机器的“开荒”，可以成为千万台机器的“本能”。**

### 1. 匿名化的经验上报
Agent 将修正后的蓝图片段进行脱敏（擦除所有个人 PII 信息，仅保留 UI 特征），通过加密通道上报至 **Swarm Hub**。

### 2. 灰度验证机制 (Canary Verification)
Swarm Hub 接收到新补丁后，不会立即推给所有用户，而是进入“共识校验”：
*   **小规模分发**：将补丁推给 1% 的同机型、同 App 版本的“探路者”设备。
*   **成功率统计**：如果在这些设备上，该补丁显著降低了 System 2 的介入频率且未引发报错，系统标记该补丁为 **“Trusted（高信）”**。

### 3. 全网热更新 (Hot-fix Propagation)
一旦确认为高信补丁，Swarm Hub 会利用 **P2P 或内容分发网络** 将更新包推送至全球。
*   **效果**：当其他用户明天打开 App 时，由于本地蓝图库已在后台静默更新，他们的 Agent 会“预知”UI 的变动，直接利用 System 1 走“快路径”避开或处理新的 UI 障碍。

## 四、 进化分层：个体记忆 vs 集体本能

| 层级 | 存储位置 | 处理对象 | 意义 |
| :--- | :--- | :--- | :--- |
| **个体记忆** | 本地缓存 (L1 Cache) | 用户私有的特定操作、特殊账号状态的 UI | 解决“我的 App 界面和你不一样”的个性化问题 |
| **集体本能** | 云端蓝图库 (Swarm DB) | 公共 App 的通用界面、版本更新、全局广告 | 解决“App 大版本迭代”导致的集体失效问题 |

---

## 五、 技术闭环：为什么要强调“回灌”？

如果不进行认知回灌，Agent 永远在“低水平重复”：
*   **无回灌系统**：每次 App 更新，所有的 Agent 都要调用一遍昂贵的大模型，浪费百万美元级别的 Token 且造成巨大的操作延迟。
*   **AceAgent-Swarm**：通过回灌，将昂贵的“探索成本”摊薄到全网。**一次探索，终身复用。**
